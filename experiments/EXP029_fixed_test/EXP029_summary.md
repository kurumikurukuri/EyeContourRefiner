# EXP029: 固定テストセット5パターン比較 — テストセット定義の妥当性検証

## 目的・仮説

`scripts/split_holdout.py` のシャッフル分割は画像リスト長（DB更新のたびに変化）に依存するため、DBにアノテーションが追加されるたびに train/test 分割が変わり、実験間の絶対値比較が無効になる問題があった（EXP028で顕在化）。

本実験では **テストセットを固定** し、かつ「どのテストセット構成法が最も信頼できる評価を与えるか」を検証するため、5パターンの選定ロジックで同一アーキテクチャ（EXP028 LN0_baseline相当）を学習・評価し比較した。

- **db_replica**: 全データの t-band 経験分布を KL 最小化 greedy で再現（母集団を代表する評価）
- **random**: 画像単位ランダム選択（分布復元を意図しないベースライン）
- **oof_error_hard**: EXP023 OOF予測の高誤差画像を fold別 greedy 選択（モデルが苦手なサンプルで評価する「難しいテスト」）
- **oof_error_easy**: 同OOF予測の低誤差画像を greedy 選択（hardの対）
- **oof_error_half**: fold別に hard上位175 + easy下位175 を組み合わせ、hard・easyそれぞれの部分集合として重なるよう設計（paired t-testでの橋渡し比較を可能にする）

## 実験設計・条件

- **実験ディレクトリ**: `experiments\EXP029_fixed_test`
- **config 数**: 5
- **config 一覧**: db_replica, oof_error_easy, oof_error_half, oof_error_hard, random
- **評価指標**: cv_mae, holdout_mae(raw t), passrate(std/strict)
- **passrate 閾値**: std=0.01788 (p10), strict=0.01604 (p5)
- **検定方法**: scipy paired t-test（per-sample abs error）
- **eye-group単位**: 1 eye-group = upper 7点 + lower 7点 の計14点（`part_name`で左右、`sub_key`でupper/lower区別）。各パターンとも `--max-eye-groups 350`（=350眼=4,900点）で統一
- **固定条件**: アーキテクチャ・ハイパーパラメータは全パターン共通（`config/baseline.yaml`、EXP028 LN0_baseline相当）、k=3 fold CV
- **変動軸**: テストセットの選定ロジックのみ

> 実装時に「1 eye-group」を誤って upper/lower 別（7点単位）でカウントしていたバグがあり（`--max-eye-groups 350` が実質175眼分しか選ばれていなかった）、途中で発覚・修正して全パターンを再学習している。最終結果は修正後（14点単位、4,900点/パターン）のもの。

## 考察

- **db_replica** と **random** は pass_std 89.3% / 89.0% とほぼ同水準で、母集団分布への近さ（KL(db_replica‖DB)=0.0000, KL(random‖DB)=0.0045）を反映して自然な結果になった。
- **oof_error_easy**（97.4%）→ **oof_error_half**（83.9%）→ **oof_error_hard**（74.4%）の順に単調に難化しており、意図した難易度スペクトラムが構築できている。half の MAE(0.1034) は hard(0.1332) と easy(0.0523) のほぼ中間で、設計通り機能している。
- oof_error_hard と oof_error_easy の選定は互いに重複ゼロ（同一 eye-group が両方に入ることはない）。oof_error_half は hard 側・easy 側それぞれと175 eye-group（=2,450点）ずつ重複するよう設計し、paired t-test での橋渡し比較を可能にした。

## t帯別結果考察

- db_replica / random ともに t<0・t>=1.2 の極端帯で pass_std が大きく落ち込む（62〜71%）傾向は過去実験（EXP016以降）と一致しており、母集団を代表する評価セットとして違和感のない結果。
- oof_error_hard/half は構成上 t<0・t>=1.2 帯がさらに悪化（40〜47%台）するが、これは「意図的に苦手サンプルを集めた」ことの反映であり、モデル自体の劣化ではない。

## ペア比較考察

- 10ペア中有意差が出たのは3つのみで、いずれも **db_replica か random が勝者**（db_replica > random、random > oof_error_easy、random > oof_error_half）。oof_error系（hard/easy/half）モデル同士は橋渡し比較を含め互いに有意差なし — 難易度構成を変えて学習しても、モデルの汎化性能自体はロバストであることを示唆。
- ただし各ペアの共通サンプル数（910〜2,450件）はペアごとに全く異なる部分集合であり、同一の固定集合で比較しているわけではない。したがって「db_replica > random」「random > easy」から「db_replica > easy」を推移的に結論づけることはできない点に注意。
- `random vs oof_error_easy` の有意差(p=0.0072)は、easy側の学習データが「モデルにとって簡単な点」を意図的にテスト側へ回した結果、対応する帯域（0.7-1.0）の学習密度がrandomよりわずかに薄くなったことに起因すると考えられる（random train: 0.7-1.0帯49.7% vs oof_error_easy train: 47.7%）。ただし各パターンとも学習は1 seedのみで、この程度の僅差(平均差0.002 in raw t)は通常の学習run-to-run分散の範囲内である可能性も残る。
- oof_error_hard/easy は EXP023（同じ構成のモデルを、ラベル修正前の DB で学習）のOOF予測に基づく選定であり、現行データで学習したモデルにとっての「真の難易度」とは完全には一致しない可能性がある点も解釈上の留保事項。

## 結論

**今後の固定テストセットとして `db_replica` を採用する。**

- `db_replica` は全データの t-band 分布との KL 距離が実質 0.0000 で、5パターン中もっとも母集団（本番相当）分布に忠実。`Completion_Criteria.md` の pass_rate 判定に使う評価セットとしては、意図的に難易度を偏らせた `oof_error_*` 系や、サンプリング運に左右される `random` より `db_replica` が適切。
- `random` は同等に近い結果だが、KL距離が非ゼロ(0.0045)かつ再生成のたびに構成が変わりうる。`db_replica` はDBスナップショットに対する決定論的な greedy 選定のため、同一シード・同一DB状態なら再現可能。
- `oof_error_hard` は「モデルの苦手ケース」を追跡する補助指標として、今後も参考値としては残す価値がある（本採用はしないが、EXP030以降でも合わせて計算し、退行がないか監視する）。

以降の実験（EXP030 データオーグメンテーション、EXP031 モデルサイズ比較 等）は `db_replica` の manifest（`manifests/manifest_{train,test}_db_replica.csv`）を標準テストセットとして使用する。

## 今後の課題

- `db_replica` は現時点の DB スナップショットに対する KL 最適化なので、今後アノテーションが大きく増えた場合は代表性がズレる可能性がある。増分が一定量を超えたら再生成を検討する。
- `oof_error_hard`/`oof_error_easy` の選定は EXP023（同じ構成のモデルを、ラベル修正前の DB で学習）の OOF 予測に基づいており、現行データで学習したモデルでの「真の難易度」とは乖離がある可能性がある。苦手ケース追跡指標として使い続けるなら、現行データで学習したモデルの OOF 予測に基づき再構築することも将来的に検討する。
- 各パターン1 seedのみの学習のため、僅差の統計的有意差（例: random vs oof_error_easy の p=0.0072）が真のパターン効果か学習run-to-run分散かは、複数seed再学習をしない限り完全には切り分けられない。
