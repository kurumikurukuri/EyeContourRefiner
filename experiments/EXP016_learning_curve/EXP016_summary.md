# EXP016: 学習曲線実験（データ量 vs Test MAE）

## 目的・仮説

- **目的**: 訓練データを 980 行ずつ削減した際に holdout test MAE がどの程度変化するかを測定し、
  目標 MAE を達成するために必要なデータ量の概算を得る。
- **対象範囲**: S08（8,107 行）〜 S12（12,880 行・全量）の 5 条件。
- **仮説**: データが多いほど MAE は単調減少し、その傾きから「目標 MAE のための必要データ量」を外挿できる。

## 実験設計・条件

- **ベース設定（EXP015 までを引き継ぎ）**: backbone=custom / loss=t / use_sigmoid=true / use_batchnorm=true /
  num_conv_layers=4 / dropout=0.3 / lr=1e-3 / wd=1e-4 / epochs=200 / batch=32 / k=3 / patience=50 / seed=42 /
  aug_flags=127 / patch_t_min=-2.0 / patch_t_max=3.0 / patch_perp_scale=2.0 / patch_h=64 / patch_w=64 /
  label_t_min=-1 / label_t_max=2
- **k=5→3 に変更**: 従来実験（k=5）との比較は不可（k が異なる）。概算目的のため k=3 で十分と判断。
- **manifest**: 本 EXP 専用で DB から再エクスポート（`scripts/split_holdout.py --exp 016`）。
  DB 増加により従来の manifest 比でトレーニングセットが 12,027 → **12,880 行**に増加。
- **サブサンプリング**: `max_train_samples` を YAML に指定し、seed=42 固定のランダムサブサンプリングで訓練データを制限。

## 結果

### 評価指標の注意

- `holdout_mae` / `cv_mae` は **正規化 t 空間**（label 範囲 3.0 で除算）の MAE。
- `test_mae` / `train_mae` は推論スクリプトによる **生 t 空間** の MAE。
- 換算: holdout_mae × 3.0 ≒ test_mae（例: S12: 0.030191 × 3.0 = 0.0906 ≈ test_mae 0.0909 ✓）

## 考察

### 1. 学習曲線は極めて平坦（データ飽和域）

holdout_mae の全範囲が **0.030191〜0.030872**（差 0.0007）で、訓練データを 37% 削減しても
test MAE は約 1% しか悪化しない。

この飽和挙動は、現在の 8,000〜13,000 行の範囲では、**データ量よりもモデル容量・アーキテクチャが精度のボトルネック**
であることを示す。単純に注釈データを増やしても大幅な改善は見込みにくい。

### 2. S09 が S08 より holdout_mae で悪化（非単調性）

S09 (9,087 行) の holdout_mae=0.030872 は S08 (8,107 行) の 0.030539 より高い（悪い）。
これは k=3 の分散（fold 分割の偶然性）による誤差の範囲内と考えられ、
単調減少への例外ではなく、**k=3 を使う際の統計的ノイズ**として解釈する。

### 3. train_mae は明確な単調減少

train_mae: 0.0784（S08）→ 0.0669（S12）は全量データで大きく低下しており、
モデルが大きなデータセットに対してより良くフィットしている。
一方で test_mae の変化は微小なため、**現在の test_mae（≈0.091）はアーキテクチャの汎化限界**に近い可能性がある。

### 4. 目標 MAE に対する必要データ量の試算

現在の傾向（test_mae ≈ 0.091）から線形外挿しても、大幅な改善には膨大なデータが必要：

| 目標 test_mae | 現在との差 | 必要追加行数（線形外挿） | 備考 |
|--------------|----------:|-------------------------:|------|
| 0.085 | −0.006 | ≈ 82,000 行 | 非現実的 |
| 0.090 | −0.001 | ≈ 14,000 行 | 微改善のみ |

これは **線形外挿の限界値であり実際はさらに厳しい**（飽和が進むにつれ効率は低下するため）。
現状の test_mae を大きく改善するには、**データ増加以外のアプローチ（アーキテクチャ改善・特徴量エンジニアリング・データ品質向上）が必要**。

### 5. 「最低限必要なデータ量」の結論

概算目的（本 EXP の本来の目的）に照らすと：

- **現在の ~8,000 行でも精度はほぼ変わらない**（test_mae ≈ 0.092 vs full 0.091）
- 精度面での「最低データ量」は ~8,000 行以下にも存在する可能性があるが、
  今回の測定範囲（8,000〜13,000 行）では飽和しており外挿が困難。
- EXP 範囲のさらに下（1,000〜5,000 行）を測定すれば急勾配領域が見つかる可能性あり。

## まとめ

- 訓練データ 8,107〜12,880 行の範囲で、**学習曲線はほぼ水平**（test_mae 変化 ≈ 0.001）。
- 現アーキテクチャでは **データ追加よりもモデル側の改善がより有効**と示唆される。
- 注釈コスト削減の観点からは、8,000 行程度まで絞っても精度劣化はごく小さい。
