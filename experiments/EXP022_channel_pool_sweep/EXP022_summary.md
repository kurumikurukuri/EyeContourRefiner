# EXP022: base_channel × pool_width 容量/分解度スイープ

## 目的・仮説

EXP021 Phase3 ベスト構成（dual X1_independent + 損失`t_l1` + aug`woflip`、raw-t MAE 0.0826）を土台に、
`EyelinerCNNDual` の容量を決める2パラメータをスイープする。

- `base_channel`: 初期チャネル数（16 / 32）
- `pool_width`: `AdaptiveAvgPool2d` 出力幅、つまり FC ヘッドに渡す特徴マップの空間分解度（1 / 8 / 16 / 32）

`base_channel=32, pool_width=32` が EXP021 Phase3 baseline と等価構成

## 実験設計・条件

- モデル・損失・aug・lr等は8条件すべてEXP021 Phase3ベスト構成に固定（dual independent, loss=t_l1, aug_flags=63, endpoint_blend_range=0.25, k=3, epochs=200/patience=50, seed=42）。変えるのは `base_channel`(16/32) と `pool_width`(1/8/16/32) の2軸のみ（直積で8条件）。
- `base_channel`: 各畳み込み層のチャネル数の基準値（`channels = [base_channel * 2**i for i in range(num_conv_layers)]`）。
- `pool_width`: 最終特徴マップに対する `AdaptiveAvgPool2d((1, pool_width))` の出力幅。高さは常に1に圧縮し、幅方向の分解度のみ変える。FCヘッド入力次元は `channels[-1] * pool_width`。
- データ分割は8条件共通（image単位）: train 663画像/12,628サンプル、holdout 304画像/8,372サンプル。train内3-fold CVで`cv_mae`、3foldアンサンブルでholdout評価。
- `passrate(std/strict)` の閾値はそれぞれ0.01788(p10) / 0.01604(p5)（`experiments/Completion_Criteria.md`準拠、`error_ratio = |t_pred-t_true|*pq_dist/eye_scale`）。
- t帯別の有意差検定は scipy の paired t-test（baseline=bc32_pw32との abs error 差を帯ごとに比較）。

## 考察

- raw-t holdout MAEで最良は **bc32_pw8 (0.087129)**、次点 bc16_pw8 (0.087208)。`base_channel` に関わらず `pool_width=8` 近傍が最も良い結果になっている。
- `pool_width=1`（実質 global average pooling）は base_channel=16/32 のどちらでも明確に悪化（0.0920 / 0.0904）。FCヘッドに渡す特徴マップの空間情報を1点まで圧縮すると位置情報が失われ、回帰精度が落ちることが確認できる。
- `pool_width=8/16/32` の間ではcv_mae・holdout_maeともに差が小さく（bc32系で0.0871〜0.0874、bc16系で0.0872〜0.0882）、8を超えて分解度を上げても明確な改善は見られない。bc16系ではむしろ8→16→32で単調に悪化する傾向がある。
- `base_channel`(16 vs 32) 単独の効果は小さいが、`pool_width=1` の極端な圧縮下ではbase_channel=32の方が明確に良い（0.0904 vs 0.0920）。空間分解度を削った分をチャネル容量で部分的に補えていると考えられる。
- passrate(strict)はbc32_pw32が最高(85.20)だが、上位構成（bc16_pw16: 85.08, bc32_pw16: 85.03, bc32_pw8: 85.02）との差は0.1〜0.2pt程度でほぼ並んでおり、raw-t MAEのランキングとは完全に一致しない。

## t帯別結果考察

- **少数派の極端t帯（t<0, t>=1.2）**では、t>=1.2 でbc32_pw8が全8条件中最良（0.2168）、t<0 でもbc16_pw8（0.3263）にほぼ並ぶ2位（bc32_pw8: 0.3274）。bc32_pw8の全体MAE改善は多数派帯への過学習ではなく、むしろ難しい極端値で効いている。
- **0-0.3帯**もbc32_pw8が最良(0.1470)で、2位のbc32_pw16(0.1499)に対しても明確な差がある。
- 一方、最多サンプル帯の**0.3-0.7**ではbc32_pw8(0.0833)はbaseline bc32_pw32(0.0819)より悪く、この帯ではbc32_pw16(0.0799)が最良。つまりpool_widthを8まで落とすことは、ボリュームゾーンの精度をわずかに犠牲にして少数派の難しい帯を改善するトレードオフになっている。
- 最多サンプル帯の**0.7-1.0**ではbc16系（pw8, pw32とも0.0660）が全体最良で、bc32_pw8(0.0667)はやや劣る。
- 総合すると、`pool_width=8` は「極端値に強いが中央値にやや弱い」、`pool_width=16` は「中央値に強いがbc32_pw8ほど極端値に強くない」という役割分担が見える。ALLでの僅差は、帯ごとの得失が相殺し合った結果と解釈できる。

## ペア比較考察

### bc32_pw8 vs bc32_pw32(baseline)
- t<0 (p=0.029)、0-0.3 (p=0.0075) でbc32_pw8が統計的に有意に改善。
- 0.3-0.7 (p=0.0027) では逆にbaselineの方が有意に良く、bc32_pw8がこの帯で犠牲を払っていることが統計的にも確認された。
- 0.7-1.0・1.0-1.2・t>=1.2は有意差なし(n.s.)。
- **ALL(全体)はp=0.347で統計的有意差なし**。holdout_mae(raw t)ではbc32_pw8(0.087129)がbaseline(0.087409)よりわずかに低いが、この差はサンプル全体で見ると誤差の範囲内であり、「bc32_pw8が全体として有意に優れている」とは言えない。改善は少数派の極端t帯に集中し、多数派帯での劣化と概ね相殺している。

### bc16_pw8 vs bc32_pw32(baseline)
- t<0 (p=0.040)・0.7-1.0 (p=0.0071) でbc16_pw8が有意に改善する一方、0.3-0.7 (p=0.040) ではbaselineの方が有意に良い。
- 0-0.3・1.0-1.2・t>=1.2は有意差なし。
- ALLもp=0.562で有意差なし。bc16_pw8はt<0ではbc32_pw8と同様に有意に改善しているが、0-0.3・t>=1.2では改善が出ておらず（t>=1.2は悪化方向）、改善の主体は多数派帯(0.7-1.0)にある。


## 結論
- holdout全体のraw-t MAEはbc32_pw8(0.087129)が8条件中最小だが、**baseline(bc32_pw32)との差はALLでは統計的に有意ではない(p=0.347)**。「全体として優れている」とは数値の上でしか支持されず、有意性の面では弱い主張である。
- 帯別に見ると評価は分かれる。少数派の難しい極端t帯（t<0: p=0.029, 0-0.3: p=0.0075）ではbc32_pw8が有意に改善する一方、最多サンプル帯(0.3-0.7: p=0.0027)ではbaselineの方が有意に良い。つまりbc32_pw8の改善は実運用上のフェイルケース（誤検出が目立つ極端t帯）に集中しており、ボリュームゾーンの精度をわずかに犠牲にした上でのトレードオフである。
- 極端t帯の精度は実運用上の重要度が高いと判断し、**bc32_pw8を次ベースラインに採用する**。ただしこれはALL指標上の優劣ではなく帯別の価値判断に基づく選択であり、ボリュームゾーンの精度を優先する用途では bc32_pw16〜32 も依然妥当な候補として残る。
- `pool_width=1`（実質global average pooling）はbase_channelに関わらず明確に劣るため除外する。
- モデルサイズの観点では、bc32_pw8はpool_widthが小さい分FCヘッドの入力次元が小さく、bc32_pw32よりパラメータ数が少ない。精度面の優位が限定的である以上、この軽量化メリットもbc32_pw8採用を後押しする一因となる。


## 今後の課題

- 今回のALL比較がn.s.だったのは、帯ごとの改善/劣化が相殺したことが一因。今後の比較では「ALLのMAE」だけでなく帯別の有意差を併記し、用途（極端t帯の検出精度を優先するか、ボリュームゾーンの精度を優先するか）に応じて構成を選ぶ運用にする。
- 今回はEXP021 Phase3固定の損失/aug構成上でのスイープのみ。base_channel/pool_widthと損失関数・aug手法の交互作用（特にt_l1損失が極端帯を重視する効き方とpool_widthの関係）は未検証。
- bc32_pw8とbc32_pw16の中間（例: pool_width=4, 12等）を追加でスイープし、0.3-0.7帯の劣化を抑えつつ極端帯の改善を維持できる分解度があるか確認する余地がある。
