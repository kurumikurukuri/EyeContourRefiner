# EXP027: perspective augmentation（顔中心ピボット + 固定パターン面外回転）

## 目的・仮説

CNN の入力 patch に **homography による透視変換（perspective augmentation）** を適用し、顔の面外回転（pitch / yaw）に対するロバスト性を向上させる。

**仮説**

1. 実世界の顔画像は pitch / yaw による foreshortening が不可避であり、通常の in-plane augmentation（回転・flip・輝度 etc.）ではカバーできない。
2. homography の回転中心を **鼻先（MediaPipe face mesh landmark #4）** に固定することで、目領域の foreshortening だけでなく顔回転に伴う orbit 移動も再現される。
3. 8 方向の固定パターン（軸 4 方向 + 対角 4 方向、各 5° 相当）で train を ×9 に展開することで、面外回転への汎化が改善する。

## 事前準備

```bash
# 1. DB に nose_x/nose_y 列を追加
python annotator/preprocessor.py --images data/images/

# 2. manifest を再生成（nose 座標カラム付き）
python scripts/split_holdout.py --exp 027
```

鼻先座標の抽出は `scr/extract_nose_coords.py` で行い、MediaPipe Face Mesh の landmark #4 を使用する。

**残差の考察**

- **fcp_p8 の全体改善（+1.03%, p=0.019）は t>=1.2 帯の残差縮小（+7.66%, p<0.001）が主因**。それ以外の帯はすべて n.s. で、ボリュームゾーン（0.3-1.0, n=7,042）の残差はほぼ不変（−0.40% / +0.73%）。外側に大きくはみ出した極端点の誤差が縮んだ、という改善の形。
- t>=1.2 帯は残差が 7.66% 縮んだのに pass_std は 61.4% → 61.4% で変化しない。この帯の残差（MAE ≈ 0.20）は閾値よりずっと大きく、誤差は縮んでも閾値の内側まで届いていない。pass_rate が MAE ほど伸びない（+0.23pt）のはこのため。
- 逆に t<0・0-0.3 帯は pass_std が +3.1pt / +2.8pt 伸びたが、残差の改善（+2.80% / +2.35%）は n.s.。点数が少なく（n=194 / 387）、通過率の伸びが偶然でないとは言えない。
- **b256 は帯ごとに改善と悪化が逆向きに出て、全体では相殺されて n.s.（p=0.31）**。0.3-0.7 帯で有意に悪化（−3.16%, p<0.001）する一方、0.7-1.0・1.0-1.2・t>=1.2 では有意に改善（+2.09〜+8.13%）。外側寄りの帯に誤差を寄せたような振る舞いで、「改善傾向だが検出力不足」ではなく、帯間のトレードオフと読むのが妥当。
- **fcp_p8 vs b256 も全体では n.s.（p=0.21）だが、帯別には逆向きの有意差がある**（0.3-0.7 は fcp_p8 が良く、0.7-1.2 は b256 が良い）。「batch size の影響は無い」のは全体 MAE についてであって、残差の分布の形は batch size で変わる。
- 帯別の p 値は 6 帯 × 3 比較の多重比較になる（Bonferroni なら有意水準 ≈ 0.003）。それでも fcp_p8 の t>=1.2 と、b256 の 0.3-0.7・1.0-1.2・t>=1.2 は p<0.001 で残る。
- 完了条件の努力目標（pass_rate 90%）に対し、fcp_p8 の pass_std 88.93% は **−1.07pt** の位置。

## 学習時間

| config | batch | train 展開 | 1 epoch 相当 | 実測時間 | 備考 |
|--------|------:|----------:|----------:|------:|------|
| EXP026 k3_b32 | 32 | ×1 (8,414) | — | **約 1 時間** | 3 folds 合計、目視推定 |
| EXP027 fcp_p8 | 32 | ×9 (75,726) | 約 2–3 時間/fold | **約 8 時間** | 3 folds + holdout 評価 |
| EXP027 b256 | 256 | ×9 (75,726) | 約 2–5 時間/fold | **約 10 時間** | 途中クラッシュ＋再開含む |

perspective augmentation による ×9 の train 展開により、学習時間は EXP026 baseline の **約 8–10 倍**に増加する。batch=256 は 1 epoch あたり高速だが、epoch 数が多い（200 vs 100）ため総時間はむしろ長い。

## 考察

1. **perspective augmentation は有意に有効**。同一 batch size（32）の非 aug baseline に対し holdout raw_t MAE が 0.08571 → 0.08483（**−1.03%, p=0.019**）。面外回転ロバスト性向上という仮説が統計的に支持された。
2. **全体 MAE では batch size の影響は無い**。batch=32 と batch=256 で MAE 差 0.00046（p=0.209, n.s.）。ただし帯別の残差には逆向きの有意差があり（0.3-0.7 は batch=32、0.7-1.2 は batch=256 が良い）、誤差の分布の形は batch size で変わる。計算効率の良い batch=32 を標準構成として推奨。
3. **b256 は有意に届かず**（全体 −0.49%, p=0.31）。帯別では 0.3-0.7 帯が有意に悪化し、外側寄りの帯（0.7 以上）が有意に改善しており、全体では相殺されている。単なる検出力不足ではなく、帯間のトレードオフと考えられる。linear scaling lr（8×）が適切でない可能性もある。
4. **学習時間は大幅増**。×9 展開により 1 時間 → 8 時間。実用上の cost/benefit は 1% 改善と 8 倍の計算時間のトレードオフ。
5. **fcp_p8 の改善は t>=1.2 帯に集中**。残差は t>=1.2 帯で +7.66%（p<0.001）縮み、他の帯は n.s.。この帯の誤差は閾値より大きいままなので、pass_std は 88.70 → 88.93%（+0.23pt）、pass_strict は 85.26 → 85.71%（+0.45pt）と、MAE の改善率（−1.03%）に比べて伸びが小さい。

## 結論

**perspective augmentation（顔中心ピボット + 8 方向固定パターン、α=1）は有効。** EXP026 k3_b32 baseline に対し holdout raw_t MAE で **−1.03% の統計的有意改善（p=0.019）**。batch size は 32 で十分であり、256 に増やしても追加改善は得られない。
改善は主に t>=1.2 帯の残差縮小（+7.66%, p<0.001）によるもので、ボリュームゾーンは不変。pass_rate は pass_std 88.93%（+0.23pt）/ pass_strict 85.71%（+0.45pt）と伸びが小さく、努力目標 90% まで −1.07pt。

## 今後の課題

- **α sweep**: α=1 以外の値（0.5, 2.0 等）で最適値を探索する余地がある。
- **pattern 数**: 8 パターン（軸 4 + 対角 4）が最適か、4 パターン（軸のみ）や 16 パターンで検証。
- **学習時間の最適化**: ×9 展開による 8–10 倍の学習時間増は実用的な課題。必要な pattern 数を見極めてコストを削減したい。
