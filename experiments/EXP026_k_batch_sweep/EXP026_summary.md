# EXP026: k(=fold数) × batch size sweep

## 目的・仮説

EXP024 で容量 3 軸（base_channel / pool_width / num_conv_layers）が全て飽和し、EXP025 で入力特徴軸（aux）も飽和した。これにより本タスクは **データ/ラベル律速** と判明した。なお EXP025 から本実験にかけて train 38件・test 39件（計 77件）の t ラベルを手動修正した（|Δ|平均 train 0.119 / test 0.136）。本実験は残る最適化系の軸 **CV fold 数 `k`** と **batch size** が holdout raw-t MAE を動かすかを検証する。

**仮説（強い事前知識）**: 容量・入力軸飽和の延長で、k/batch も概ね飽和しており、現行デフォルト `k=3, batch=32` がほぼ最適、と予測する。

**ただし `k` は特殊軸**: `k` を変えると ①fold あたりの学習データ量（k=5 なら 4/5、k=3 なら 2/3）と ②holdout 評価時のアンサンブル枚数（fold モデルを全て平均）が **同時に** 変わる。純粋な容量軸とは異なるため、実測で確認する価値がある。

## 実験設計・条件

- **サンプル**: manifest_train.csv 12,628件 / manifest_test.csv 8,372件（EXP025 と同一 idx。t ラベルを計 77件修正: train 38件・test 39件）
- **config**: `experiments/EXP026_k_batch_sweep/config/{k3_b32,k3_b64,k4_b32,k4_b64,k5_b32,k5_b64}.yaml`（train: `scr/train_exp026.py`）
- **主要ハイパーパラメータ**: epochs=200, lr=1e-3, weight_decay=1e-4, patience=50, seed=42。**スイープ軸**は k∈{3,4,5} × batch∈{32,64} の 6 構成。
- **固定する条件 / 変える条件**: モデル構造・損失・aug は EXP025 A0（= EXP024 bc32_pw8 baseline）に完全固定（`custom_dual`, `fusion_mode=independent`, `pq_rescale_mode_b=eye_scale`, `loss_fn=t_l1`, `base_channel=32`, `pool_width=8`, `num_conv_layers=4`, `aug_flags=63`, `endpoint_blend_range=0.25`, `aux_features=[]`, `use_is_upper=true`）。変えるのは **k と batch のみ**。

  | config | k | batch | 役割 |
  |-----|---|------|------|
  | **k3_b32** | 3 | 32 | **baseline/anchor** = 現行デフォルト |
  | k3_b64 | 3 | 64 | batch 効果（k=3 固定） |
  | k4_b32 | 4 | 32 | fold 数効果（batch=32 固定） |
  | k4_b64 | 4 | 64 | |
  | k5_b32 | 5 | 32 | fold 数効果（大アンサンブル） |
  | k5_b64 | 5 | 64 | |

- **データ**: manifest_train.csv 12,628件 / manifest_test.csv 8,372件。holdout（test）は k に依らず固定のため、6 構成は同一 test set での公平比較。train 側のみ k 分割が変わる。
- **評価指標**: cv_mae, holdout_mae(norm/raw t), passrate(std/strict)。閾値は `experiments/Completion_Criteria.md` 準拠（std=0.01788, strict=0.01604）。

## 考察

事前仮説「k/batch 軸も飽和しており k3_b32 がほぼ最適」は概ね支持された。

- **batch 効果（k=3 固定）**: batch=64（k3_b64）は baseline より MAE が +0.00085 悪化し、後述のpaired t-test でも p=0.003（**）で有意に劣る。batch=32 が優位であることが実測でも確認された。
- **fold 数効果（batch=32 固定）**: k=4（k4_b32）は p=0.51（n.s.）で baseline と差なし。k=5（k5_b32）は p=0.041（*）で有意に劣る。fold を増やしても汎化は改善しない。
- **passrate(strict)**: k5_b64 のみ 85.73% と baseline（85.26%）を 0.47pt 上回るが、raw-t MAE は baseline より悪い（0.086096 vs 0.085711）。t>=1.2 帯の MAE が k5_b64 は 0.2177 で baseline（0.2178）とほぼ同等であり、passrate 向上は統計的に偶発的な可能性が高い。
- **cv_mae は k が増えると微減**（k5_b64=0.02927 は最小）だが、holdout MAE には反映されない。OOF 評価の安定性が上がるだけで、汎化は変わらない。
- **結論として k=3, batch=32 を現行デフォルトとして維持する**。k/batch はコスト（学習時間）を増やすだけで holdout MAE の改善には繋がらない。

## t帯別結果考察

- 最大帯（**0.6-0.9**, n=4,231）では k5_b32/k5_b64 が baseline より僅かに良い（0.06508 vs 0.06566）。ここが全体 MAE の主要寄与帯だが差は小さい。
- **t<0 帯**（極端値・小サンプル n=194）では k4_b32 が 0.3209 と最良。ただしこの帯はサンプルが少なく変動大。
- **t>=1.2 帯**（極端値, n=171）では k3_b64/k4_b64 が最良だが、どの構成も ~0.21 で拮抗。
- 帯別で特定の k/batch が全帯域で baseline を上回ることはなく、「全帯域で優れた単一構成」は存在しない。これは飽和の典型的パターン。

## ペア比較考察

- **k3_b64（批判的）**: batch=64 は baseline より有意に悪い（p=0.003, **）。1% の悪化は小幅だが再現性あり。ミニバッチが大きくなると勾配の多様性が下がり収束先が浅くなる可能性。
- **k4_b32, k4_b64, k5_b64**: いずれも n.s.。有意な差なしで「同等」と判断できる。
- **k5_b32**: p=0.041（*）で有意に悪い。fold 数を増やしても fold あたりのデータが増えることによる恩恵が得られず、むしろ学習コスト（5 fold × モデル）だけが増える。

## 結論

**k=3, batch=32（k3_b32）を採用・維持する。**

- 全 5 対比で baseline を有意に上回る構成はゼロ。
- batch=64 と k=5 は有意に悪い（** / *）。
- EXP024（容量軸）・EXP025（入力特徴軸）と合わせ、**本タスクは既にデータ/ラベル律速の飽和状態にある**ことを k/batch 軸でも確認。
- 次に MAE を改善するには、アーキテクチャ以外の軸（ラベル品質向上・データ拡充・損失関数の見直し・タスク定式化の再検討）が必要。

## 今後の課題

- ラベル修正・追加アノテーションによるデータ品質向上
- t<0 / t>=1.2 帯（極端値）の集中的なラベルレビュー（サンプル数が少なく精度が低い）
- 損失関数の見直し（L1 以外のロバスト損失、帯別重み付けなど）
